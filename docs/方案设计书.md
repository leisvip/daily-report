# 🛠️ AI 日报自动生成系统 — 方案设计书

> **目标**：让 AI 助手在完成每个任务后，自动记录并生成日报向用户汇报
>
> **状态**：✅ 已完成（v1.1.0 — 已集成 OpenClaw 消息推送）

---

## 一、核心思路

```
用户下达任务 → AI 执行任务 → 任务完成 → 自动记录到日志 → 触发日报生成 → 向用户推送日报
                                    ↑                                              ↓
                                    └──────────── 用户看到今天的"工作清单" ────────────┘
```

**本质**：给 AI 装一个"自动记工时"的仪表盘，每完成一件事就打卡，结束时交一份日报。

## 三、执行流程（详细）

### 3.1 任务记录流程

```
Step 1: AI 完成一个任务
            │
            ▼
Step 2: 调用 task-tracker.sh 记录任务
            │
            ├── 任务类型（需求/Bug/Review/文档/技术建设/其他）
            ├── 任务名称
            ├── 任务描述（一句话）
            ├── 量化数据（代码行数/文件数/耗时等）
            ├── 关联文件（可选）
            └── 状态（完成/进行中/阻塞）
            │
            ▼
Step 3: 追加写入 data/YYYY-MM-DD.jsonl（每行一条 JSON）
            │
            ▼
Step 4: 如果是当天最后一个任务 → 触发日报生成
```

### 3.2 日报生成流程

```
Step 1: 读取当天 data/YYYY-MM-DD.jsonl
            │
            ▼
Step 2: 按任务类型分类汇总
            │
            ├── 🔴 需求开发
            ├── 🟡 Bug 修复
            ├── 🔵 Code Review
            ├── 🟢 技术建设
            ├── 📝 文档输出
            └── 🔧 其他
            │
            ▼
Step 3: 计算量化指标
            │
            ├── 总任务数
            ├── 各类型任务数
            ├── 代码行数统计
            └── 预估耗时
            │
            ▼
Step 4: 套用模板生成 Markdown 日报
            │
            ▼
Step 5: 保存到 reports/YYYY-MM-DD.md
            │
            ▼
Step 6: 推送到聊天窗口（精简版）
```

### 3.3 推送格式（精简版）

```markdown
═══════════════════════════════════════

═══════════════════════════════════════

✅ 完成任务 5 个

  1. 解压并分析 MiMo Chat CLI 项目
  2. 编写周报模板大全文档（15,000+ 字）

🔧 其他 (3)
  3. 下载并保存文件
  4. 执行 mimo CLI 对话测试
  5. 生成日报系统方案设计

  · 文档产出：15,000+ 字
```

## 四、技术方案

### 4.1 方案选型

| 方案 | 语言 | 优点 | 缺点 | 推荐度 |
|------|------|------|------|--------|
| **A. Shell + Python** | bash + python | 轻量、无依赖、灵活 | 需要两个脚本 | ⭐⭐⭐⭐⭐ |
| B. 纯 Node.js | node | 一个文件搞定 | 需要 node 环境 | ⭐⭐⭐ |
| C. 纯 Shell | bash | 最轻量 | JSON 处理麻烦 | ⭐⭐ |
| D. OpenClaw Skill | md + 脚本 | 深度集成 | 需要安装 | ⭐⭐⭐⭐ |

**决策**：采用 **方案 A**（Shell + Python），因为：
- Shell 脚本负责记录（简单追加，零依赖）
- Python 脚本负责生成（JSON 处理、模板渲染能力强）
- 两个脚本职责单一，易于维护

### 4.2 task-tracker.sh（任务记录器）

**功能**：接收任务信息，追加写入当日 JSONL 日志

**调用方式**：
```bash
# 基础用法
./task-tracker.sh -t "需求开发" -n "解压分析项目" -d "解压 MiMo Chat CLI 并通读代码"

# 完整用法
./task-tracker.sh \
  -t "需求开发" \
  -n "编写周报模板" \
  -d "编写打工人周报日报月报模板大全" \
  --lines 15000 \
  --files 1 \
  --status "done" \
  --tags "文档,写作"
```

**参数说明**：
| 参数 | 必填 | 说明 | 示例 |
|------|------|------|------|
| `-t, --type` | ✅ | 任务类型 | 需求开发 / Bug修复 / Review / 文档 / 技术建设 / 其他 |
| `-n, --name` | ✅ | 任务名称（一句话） | "解压分析项目" |
| `-d, --desc` | ❌ | 任务描述（详细） | "解压并通读 6 个文件..." |
| `--lines` | ❌ | 代码/文档行数 | 15000 |
| `--files` | ❌ | 涉及文件数 | 6 |
| `--commits` | ❌ | Git commit 数 | 5 |
| `--bugs` | ❌ | 修复 Bug 数 | 3 |
| `--reviews` | ❌ | Review 次数 | 2 |
| `--duration` | ❌ | 耗时（分钟） | 30 |
| `--status` | ❌ | 状态（默认 done） | done / wip / blocked |
| `--tags` | ❌ | 标签（逗号分隔） | "文档,写作,重构" |
| `--files-changed` | ❌ | 关联文件路径 | "/root/xxx/file.md" |

**输出格式**（JSONL，每行一条）：
```json
{
  "ts": "2026-04-29T02:25:00+08:00",
  "type": "需求开发",
  "name": "解压分析项目",
  "desc": "解压 MiMo Chat CLI 并通读代码",
  "metrics": {
    "files": 6,
    "lines": 0,
    "commits": 0,
    "bugs": 0,
    "reviews": 0,
    "duration_min": 0
  },
  "status": "done",
  "tags": ["解压", "分析"],
  "files_changed": []
}
```

### 4.3 report-generator.py（日报生成器）

**功能**：读取当日 JSONL 日志，生成格式化日报

**调用方式**：
```bash
# 生成今天的日报
python3 report-generator.py

# 生成指定日期的日报
python3 report-generator.py --date 2026-04-29

# 生成精简版（用于聊天推送）
python3 report-generator.py --brief

# 生成周报
python3 report-generator.py --week

# 生成月报
python3 report-generator.py --month
```

**生成逻辑**：
```python
1. 读取 data/YYYY-MM-DD.jsonl
2. 按 type 分类汇总
3. 计算总指标（任务数、代码行数、文件数等）
4. 套用模板渲染 Markdown
5. 保存到 reports/YYYY-MM-DD.md
6. 如果 --brief，输出精简版到 stdout
```

**日报模板**：
```markdown
# 📋 今日日报 - {日期}（{星期}）

## 📌 今日概述
> {AI 自动生成的一句话总结}

## ✅ 今日完成（共 {N} 个任务）

### 🔴 需求开发 ({count})
1. **{name}** ✅
   - {desc}
   - 量化：{metrics}

### 🟡 Bug 修复 ({count})
...

### 🟢 技术建设 ({count})
...

### 📝 文档输出 ({count})
...

## 📊 量化数据

| 指标 | 今日 |
|------|------|
| 总任务数 | {total} |
| 代码/文档行数 | {lines} |
| 涉及文件数 | {files} |
| Git Commit | {commits} |
| Bug 修复 | {bugs} |
| Code Review | {reviews} |

## 🚧 进行中
{wip_tasks}

## ⚠️ 阻塞项
{blocked_tasks}

---
*自动生成于 {timestamp}*
```

## 六、我（AI）的工作流改造

### 6.1 改造前

```
用户：帮我写个文档
AI：写好了 ✅
（结束，没有记录）
```

### 6.2 改造后

```
用户：帮我写个文档
AI：写好了 ✅
    ↓
    [自动记录] 调用 task-tracker.sh 记录本次任务
    ↓
    如果是今天第 N 个任务 → 询问用户是否要看日报
    ↓
    用户：看日报
    ↓
    [生成日报] 调用 report-generator.py --brief
    ↓
    推送精简日报
```

### 6.3 具体行为规则

| 场景 | AI 行为 |
|------|---------|
| 完成第 1 个任务 | 静默记录，不打扰用户 |
| 完成第 3 个任务 | 提示一句："今日已完成 3 个任务，随时可以查看日报" |
| 完成第 5+ 个任务 | 每完成一个，提示是否要生成日报 |
| 用户说"日报/总结" | 立即生成并推送 |
| 用户说"周报/月报" | 汇总对应时间段的数据生成 |
| 用户说"今日统计" | 推送精简版量化数据 |

## 十一、风险与限制

| 风险 | 影响 | 应对 |
|------|------|------|
| AI 重启后丢失当日任务计数 | 日报不完整 | 任务实时写入文件，不依赖内存 |
| JSONL 文件过大 | 性能问题 | 按月归档，每月初压缩上月数据 |
| 任务分类不准确 | 日报分类混乱 | 允许用户手动修正类型 |
| AI 忘记记录 | 日报缺失 | AGENTS.md 中写入强制规则 |
